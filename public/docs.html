Local storage, explicit model roles, and a transcript-first integration API. Everything here matches the server in this repository.

Quickstart

Run locally

Install Bun 1.2 or later, then copy the configuration in the project directory:

● ● ●configure
cd sabbia-app
cp .env.example .env

Set NVIDIA_API_KEY in .env to your provider key, or set SABBIA_MOCK=1 for deterministic offline inference. Then start the single process:

● ● ●local / run
bun run src/index.ts      # → http://localhost:3000

Open the website or the console. Bun reads .env automatically; process environment variables take precedence. In PowerShell, copy the file with Copy-Item .env.example .env.

Run with Docker Compose

In the project directory, create .env and configure a key or mock mode before starting:

● ● ●docker / compose
cp .env.example .env
# Set NVIDIA_API_KEY or SABBIA_MOCK=1 in .env.
docker compose up --build -d
docker compose logs -f sabbia

Compose publishes port 3000 and persists SQLite and uploads in ./data:/data. A keys file needs its own volume mount and a container-relative NVIDIA_KEYS_FILE path. Scanned-PDF OCR requires optional pdftoppm; the base Docker image does not install it.

Deployment scope

The public API needs no login. Use HTTPS, visitor cookie isolation, abuse limits, and an optional operator token for destructive routes. The reverse proxy must overwrite X-Forwarded-For with the trusted first client hop and restrict direct listener access.

Limits and abuse protection

The API is open by default. The daily model budget is the cost guard: lower it to tighten spending or raise it for more capacity, then restart. It counts model route admissions, not tokens or dollars, and persists in SQLite across restarts. The dispatcher charges POST thread turns, vision analyses, voice turns, and corpus searches before execution, including local replies and invalid bodies. PDF uploads also reserve a unit because scanned documents can use OCR. Already admitted work can finish. Minute/hour token buckets refill continuously and remove idle clients; maps hold at most 10,000 identities. Use a single process: stream and minute limits are in-process. There is also a 128 concurrent request admission cap and a 100,000 visitor identity cap.

StatusMeaning
401Operator token missing or incorrect on a protected destructive route.
409Corpus source count exceeded, or visitor cleanup in progress.
413File exceeds the per-file ceiling or JSON body exceeds 256 KiB.
429Request, model, upload, stream, daily budget, or identity/concurrency capacity exceeded. application/problem+json names the limit and next availability/reset; numeric Retry-After gives seconds to wait. A spent public demo budget resets at 00:00 UTC. Stream availability uses a five-second retry estimate.
507Stored uploads exceed the aggregate quota (detail includes current and maximum bytes), or SQLite reaches its separate metadata ceiling. Shared upload objects count once. Leave disk space for WAL and PDF temporary files as well.

Search queries longer than 2,000 characters return 400. SSE connections expire after five minutes and close for slow readers with excessive queued events. The console shows friendly inline 429/507 notices and keeps Send disabled while streaming.

Visitor privacy and data controls

Each visitor receives a 32-byte random base64url sabbia_visitor cookie: HttpOnly; Secure; SameSite=Lax, expiring in 30 days. HTTPS is required for public use. API clients must retain and resend it. Only its SHA-256 hash and timestamps are stored; no IP or personal data is recorded. Losing the cookie loses access. Threads, corpora, and assets have visitor ownership. Lists show only the caller's own records. Direct-by-id reads and writes, SSE replay, voice, sources, images, searches, and thread model usage are scoped; another visitor receives 404. Existing rows remain NULL-owned operator data; a valid operator token permits direct access to legacy rows, without granting access to other visitors.

A read-only shared demo corpus (is_public=1), seeded at boot from bundled English and Chinese text, keeps knowledge search working for new visitors who own no corpus. GET /v1/demo/corpus discovers it; the console creates a private corpus on upload.

DELETE /v1/threads/:id, DELETE /v1/sources/:id, and DELETE /v1/voice/sessions/:id are public only while SABBIA_AUTH_TOKEN is unset (local single-user mode). When configured they require Authorization: Bearer or X-API-Key, checked in constant time; otherwise 401. Ownership checks still apply. All other public API access remains without a login. Set the token on a public deployment.

GET /v1/visitor/export returns the caller's threads, turns, corpus metadata, and source titles. DELETE /v1/visitor removes all caller-owned data and clears the cookie without requiring the operator token. Both controls are in the console footer. The hourly retention sweep (also at boot) removes anonymous rows and uploaded objects older than SABBIA_RETENTION_DAYS and logs counts; NULL-owned operator rows are never removed.

The operator can inspect local SQLite access_log records: id, at, visitor_hash, method, route, resource_kind, resource_id, status. Only reads and deletes are audited; no bodies, IPs, or raw cookies. Records are capped at 100,000 and pruned by retention. /healthz reports audit counts, limits (model_remaining_today, model_budget_per_day, streams_open), and storage (used_mb, limit_mb, sources), never raw audit rows. /api/config uses dataDirConfigured instead of a filesystem path. Provider key material and prefixes remain private.

Reasoning vision token budget

Reasoning vision models need max_tokens ≥ 1200; with a smaller budget the chain of thought consumes the whole response and the content comes back empty.

The primary vision role normally uses 1400 tokens, enforces a minimum of 1200, and retries once at 2800 if reasoning is present but content is empty. The alternate vision path has a 15-second timeout and one retry before falling back to the primary model. Public image analysis defaults to visionMain.

Request rules

  • Thread surfaces: console, knowledge, support, voice, and vision.
  • Knowledge and Console accept corpusId. When omitted, retrieval uses the oldest corpus; Support and Voice also use that default.
  • Vision tasks: describe, text, table, and qa. The qa task requires question. Table extraction can return {"text":"…","format":"plain_text"} if structured parsing fails.
  • Poll GET /v1/sources/:id after ingestion; wait for indexed before querying. A duplicate upload returns the existing source with deduplicated: true.
  • Errors use application/problem+json with detail and trace_id; the response also includes x-trace-id.

Event stream

Each SSE frame has an id matching its per-thread sequence number and a JSON data payload with v: 1, seq, and kind. The event journal is stored in SQLite.

turn.start
Starts a user or assistant turn; identifies its turn ID and author.
block.open
Opens an assistant content block, such as text.
text.delta
Adds the next text fragment to the assistant’s reply.
citations.set
Provides source citations and excerpts for the answer.
tool.request
Records a requested operation, such as search or escalation.
tool.result
Records the operation’s returned data or ticket.
guardrail.verdict
Records an input or output guard rule and its verdict.
agent.handoff
Reports the selected agent, routed intent, confidence, and human-review flag.
turn.end
Finishes a turn with usage and, where applicable, a verdict or failure flag.
error
Reports a failed turn with a readable detail message.

Resume after a disconnect

GET /v1/threads/:id/events?after=<seq>

Persist the last processed sequence number and request events strictly after it. You can also send Last-Event-ID; the server uses the larger of that header and after. Replay is followed by live events. Frames include a 3000 ms retry hint, and idle streams receive a heartbeat every 15 seconds. Ignore already processed sequence numbers to avoid duplicates.

POST /v1/threads/:id/turns streams the submitted turn’s events and closes on completion. GET /v1/threads/:id/events stays subscribed.

Troubleshooting

Empty vision response

Raise max_tokens in src/models.ts. Reasoning can consume the budget before any content is produced; use at least 1200 tokens. The primary client already retries an empty reasoning response at 2800.

Function '…' not found for account

That model is not enabled for your key. Verify the account’s model access; the provider’s discovery list is not an entitlement list.

Provider returns 429

The key pool rotates automatically. Check /healthz for usable and cooling keys. Cooldowns start at 5 seconds, double after failures, and cap at 5 minutes. If every key is cooling, wait for retry availability.

Ingestion is in failed

Read fail_reason on the source using GET /v1/sources/:id. Check the file format and extraction error. An interrupted ingestion is marked failed on restart; remove the source and upload it again.

Voice integration

Voice consumes transcripts. Your telephony stack owns audio transport, speech-to-text (STT), text-to-speech (TTS), and playback interruption. Browser audio capture is outside the product.

  1. Create a session with POST /v1/voice/sessions and JSON {}. Save its sessionId and threadId.
  2. Transcribe a caller line in your application, then send it to the session:
POST /v1/voice/sessions/:id/turns
Content-Type: application/json

{"speaker":"caller","transcript":"I need help with a return.","interrupted":false}

The JSON response includes reply, latency_ms, and verdict (allow, redact, refuse, or escalate). Send the returned reply to your TTS service. Caller input and assistant output are checked by the conversation guardrails.

Set interrupted: true when a caller interrupts playback; this marks the previous assistant segment interrupted. An assistant transcript only logs that segment and returns an empty reply with zero latency; it does not invoke a model.

GET /v1/voice/sessions/:id

{"id":"session-id","thread_id":"thread-id","started_at":"2026-10-27T12:00:00.000Z","ended_at":null,
 "segments":[{"speaker":"caller","transcript":"I need help with a return.",
              "start_ms":1000,"end_ms":2714,"interrupted":0}]}

Fetch this session endpoint for persisted segments. Start offsets are measured from session creation; end offsets are estimated from transcript length, not measured audio. Calls are serialized per thread. The Voice transcript console lets you test this flow with text and start a new session.
